# Task 02 - Missing Database Indexes

## Scenario

Hot queries filter and sort by `CustomerId`, `ProductId`, and `CreatedAt`, but the model intentionally does not define indexes for these columns.

## Endpoints

```http
GET /api/orders/recent
GET /api/orders/customer/1/history
GET /api/products/{id}
GET /api/products/popular
```

## Where to look

- `PlaygroundProject/Data/SpeedyShopDbContext.cs`
- `PlaygroundProject/Services/OrderWorkshopService.cs`
- `PlaygroundProject/Services/ProductWorkshopService.cs`

## Symptoms

- Slow database spans for simple filters.
- Table scans become expensive as seed data grows.
- Recent orders and product review lookups degrade with larger datasets.

## How to measure

- Compare endpoint latency with development seed data vs larger seed data.
- Inspect SQL generated by EF Core in logs/traces.
- Use SQLite query plans or SQL Server execution plans if running with SQL Server.

## Goal

Add appropriate indexes for the access patterns.

## Possible fixes

- Add indexes for:
  - `Orders(CustomerId)`
  - `Orders(CreatedAt)`
  - `Reviews(ProductId)`
  - `Reviews(CreatedAt)`
  - `Products(CreatedAt)`
- Consider composite indexes such as `Orders(CustomerId, CreatedAt)`.

## Success criteria

- Database spans become shorter for filtered endpoints.
- Query plans show index usage.
- Larger seed sizes remain responsive.
